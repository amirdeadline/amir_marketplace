## 1. Overview

amir_md is a Markdown editor that works like Microsoft Word. You open a Markdown file and edit formatted text directly: headings, fonts, colors, links, and images. You never type Markdown syntax. A navigation pane shows the document's headings as a tree, and every heading in the document can be folded, the same way Word folds headings.

The file on disk stays plain Markdown. It still works with Git, diff tools, code review, and every other Markdown viewer. amir_md also exports the document to PDF and to Word.

amir_md ships first as a VS Code extension. A Windows desktop app follows later, built on the same editor UI.

### 1.1 The problem

Long technical documents are often written in Markdown because Markdown diffs cleanly, generates easily from scripts, and lives well in Git. The Prisma SD-WAN Maturity Assessment guide is a good example: about 7,700 lines, 295 headings, and 193 checks, with tables and inline HTML. Editing a file like that means reading raw syntax, pipe tables, and HTML tags.

A read-only navigator built for that guide showed how much a heading tree and collapsible sections help with long documents. It cannot edit, and it has to be regenerated by a script after every change.

Word solves editing and navigation, but its files are binary. They do not diff, merge, or generate well.

amir_md gives Word-style editing and navigation on top of plain Markdown files.

## 2. Goals and non-goals

### 2.1 Goals

| ID | Goal |
|---|---|
| G1 | Edit Markdown as formatted text, without seeing or typing Markdown syntax. |
| G2 | Move around long documents with a heading tree that can expand and collapse one heading level at a time. |
| G3 | Fold any section in the document, from Heading 1 to Heading 6, the way Word does. |
| G4 | Keep the file clean. Opening and saving without edits changes nothing. An edit changes only the blocks that were edited. |
| G5 | Export to PDF and Word, with headings mapped to Word's own heading styles. |
| G6 | Run inside VS Code on Windows now, and as a Windows app later with the same UI. |

### 2.2 Non-goals for version 1

- Real-time co-editing with other people.
- Word-style track changes and margin comments.
- Special rendering for project-specific syntax, such as the MA guide's claim labels, result-state badges, and `[{C-NNNN: ...}]` review notes. These stay as plain text in version 1. A renderer plugin can add them later.
- Importing Word or PDF files into Markdown.
- Drawing or editing diagrams (Mermaid and similar).
- Page layout features inside the editor, such as columns, section breaks, and running headers.

## 3. Users

| Persona | Who they are | What they need |
|---|---|---|
| Author | Writes and maintains long technical guides, often generated in part by scripts. | Word-style editing, fast navigation, clean Git diffs. |
| Reviewer | Reads documents, makes small fixes, and shares them with customers or managers. | Folding to focus, quick edits, one-click PDF and Word export. |
| Engineer | Edits runbooks, READMEs, and design notes in VS Code, from junior to senior level. | A familiar Word-like toolbar so they do not need to learn Markdown. |

## 5. Feature requirements

### 5.1 Open and save

|---|---|---|
| PRD-01 | Open any `.md` or `.markdown` file in amir_md from the Explorer context menu, the command palette, the editor title bar, or VS Code's "Reopen Editor With". | Must |
| PRD-02 | Offer a setting that makes amir_md the default editor for Markdown files. It is off by default. | Should |
| PRD-03 | Save with Ctrl+S to the same Markdown file. Unsaved-changes indicator, undo, redo, auto-save, and hot exit behave as they do for any VS Code editor. | Must |
| PRD-04 | Save As to a new Markdown file. | Must |

### 5.3 Folding sections in the document

## 6. User experience

### 6.1 Layout

```
+-------------------------------------------------------------------------------+
| Undo Redo | Normal text v | Aptos v | 11 v | B I U S | A v  H v | Clear       |
| Bullets Numbers Tasks  Outdent Indent | Link Image Table Quote Code | Export v |
+--------------------------+----------------------------------------------------+
| Filter headings          | 3 Branch > 3.2 Circuits > 3.2.3 Bandwidth          |
| [ search box           ] |                                                    |
|     [All v] [Expand] [Collapse]                                               |
| 295 headings             |  v 3.2 Circuits                                    |
|--------------------------|      Text of section 3.2 ...                       |
| v 0 Preparation          |    > 3.2.1 The branch has the circuits ... (folded)|
|   > 0.1 How to use       |    v 3.2.2 Each circuit has the right category ... |
| v 1 Global               |      Text of section 3.2.2 ...                     |
|   > 1.1 Tenant identity  |                                                    |
+--------------------------+----------------------------------------------------+
| Saved | 12,340 words | amir_md                                                |
+-------------------------------------------------------------------------------+
```

- Toolbar across the top, grouped like the Word ribbon: history, style, font, character formatting, color, lists, insert, export.
- Navigation pane on the left, resizable and hideable.
- The document on the right, laid out like a page.
- Status line at the bottom: save state and word count.

### 6.2 Navigation pane controls

The filter box keeps its own row. Under it, the controls sit against the right edge of the pane:

```
[ All      v ]  [ Expand ]  [ Collapse ]
```

The level list is to the left of Expand. Its options are All, Heading 1, Heading 2, Heading 3, Heading 4, and Heading 5.

| Level selected | Expand | Collapse |
|---|---|---|
| All | Opens every entry. | Closes every entry. |
| Heading N | Opens every Heading N entry that has children, and opens the entries above it so it is visible. | Closes every Heading N entry. |

Entries at other levels keep whatever state they had.

### 6.3 Folding triangles

- A small triangle sits in the left margin, next to the first line of every heading.
- Hovering over the triangle or the heading makes the triangle larger and shows that it is clickable.
- The triangle points down when the section is open and right when it is folded.
- A folded heading's triangle stays visible, so folded sections are easy to spot.

| Phase | Scope |
|---|---|
| Phase 0: spikes | Four short experiments before building: editor round-trip fidelity, Word export, PDF export through Edge, and keyboard shortcuts and undo inside a VS Code webview. Details in the SRS. |

## 8. Success measures

| Measure | Target |
|---|---|
| No-op save | Byte-identical on every file in the test corpus, including the MA guide. |
| Edit footprint | Editing one paragraph changes only that paragraph's lines in the Git diff. |
| Open time | The MA guide shows its first content in under 2 seconds on a typical Windows laptop, and the navigation tree is ready under 1 second after that. |
| Typing | Under 50 ms from key press to screen update in the MA guide. |
| Word export | Every heading in the exported file uses the matching Word heading style. |
| Ease of use | A new user completes the stories in section 4 without touching Markdown syntax. |

## 9. Risks

| ID | Risk | What we do about it |
|---|---|---|
| R1 | Most visual Markdown editors rewrite the whole file on save, which breaks clean diffs. | Rewrite only the blocks that changed, keep unknown content as source blocks, and test against a corpus in spike S1. |
| R2 | VS Code catches some shortcuts before the editor sees them (for example Ctrl+K chords). | Register amir_md shortcuts only while amir_md is the active editor, test them in spike S4, and offer alternatives. |
| R3 | PDF export needs a Chromium browser. | Use Edge, which ships with Windows. Fall back to Chrome or Pandoc, and show clear steps when none is found. |
| R4 | Very long documents can feel slow. | Incremental parsing, debounced updates, CSS-only folding, and a virtual tree above 1,000 headings. |
| R5 | Inline HTML styling is not portable. GitHub removes `style` attributes, so colors and fonts do not show there. | Use standard Markdown for everything Markdown supports, and document the limit. |
| R6 | Showing HTML from a file inside the editor carries a security risk. | Sanitize HTML for display and apply a strict content security policy. |
| R7 | Fonts that are not installed change how exports look. | Fall back to standard fonts; the PDF engine embeds the fonts it uses. |

## 10. Open questions

| ID | Question | Proposed answer |
|---|---|---|
| Q1 | When a folded heading is deleted, should its hidden text go too? | Yes, like Word, with undo and a status message (PRD-38). |
| Q2 | How should Title and Subtitle be stored, since Markdown has no such styles? | As an HTML paragraph with a data attribute and a font size, for example `<p data-amir-style="title" style="font-size:26pt;">`. The alternative is YAML front matter, which allows only one title per file. |
| Q3 | Which desktop shell for the Windows app: Electron or Tauri? | Decide at the start of Phase 2. Electron reuses the export code and prints to PDF natively; Tauri produces a much smaller app and uses Edge WebView2. |
| Q4 | Should amir_md become the default Markdown editor when installed? | No. Keep it opt-in through a setting (PRD-02). |
| Q5 | How is the extension distributed: a private VSIX or the VS Code Marketplace? | Start with a VSIX built the same way as the existing amir extension. |

## 11. Glossary

| Term | Meaning |
|---|---|
| ATX heading | A Markdown heading written with `#` characters, for example `## Section`. |
| CommonMark | The standard specification of Markdown syntax. |
| GFM | GitHub Flavored Markdown. CommonMark plus tables, strikethrough, task lists, and autolinks. |
| Custom editor | A VS Code feature that lets an extension replace the text editor with its own UI for a file type. |
| Webview | The embedded browser panel a VS Code extension uses to show its own UI. |
| Fold | Hiding a section's content under its heading without changing the file. |
| Source block | A block amir_md keeps exactly as written because it cannot show it as formatted text. |
| VSIX | The installable package file for a VS Code extension. |
| Pandoc | A free command-line document converter that can turn Markdown into Word and PDF. |
