# amir — workspace rules

Project layout, agent workspaces, write permissions, and isolation.

**Authoritative create/onboard layout:** `amir_system` plugin
`templates/project-layout.md`. Follow that file for directory placement.

## Separation rule

| Kind of data | Where |
|---|---|
| Shared project facts (goal, status, TODO, design, assumptions, tasks, report index) | `.ai/` |
| Cursor agents, skills, rules, commands, Cursor settings | `.cursor/` |
| Claude agents, skills, Claude settings | `.claude/` |
| Codex agents, Codex settings | `.codex/` |
| IDE chrome / theme | `.vscode/` |
| Amir manifest / lock / portfolio | `.amir/` |

## Shared project docs under `.ai/`

Required markdown (seeded on create/onboard):

```
.ai/
├── settings.json
├── TODO.md
├── project.md
├── status.md
├── assumptions.md
├── design.md
├── tasks.md
├── reports.md              # index table → host agent report.md files
├── decisions.md
├── risks.md
├── architecture.md
├── references.md
├── changelog.md
├── context_handoff.md
├── state/                  # optional — amir_project harness JSON truth
│   ├── tasks.json
│   ├── decisions.json
│   ├── status.json
│   ├── activity.jsonl
│   └── cost.json
└── views/                  # optional — regenerated markdown from harness tools
```

Do **not** put new host agent workspaces under `.ai/agents/`. Legacy `.ai/agents/` may
exist in older projects; new work uses host paths below.

## Host agent workspaces

```
.cursor/agents/<agent-id>/report.md
.claude/agents/<agent-id>/report.md
.codex/agents/<agent-id>/report.md
```

Minimum agents when orchestration is enabled: `orchestrator`, `qa` (under each enabled host).

Each agent workspace may also hold `notes.md`, `prompt.md`, `handoff.md`, `logs/` as needed.
`report.md` is mandatory. After writing/updating `report.md`, update `.ai/reports.md`
(columns: Agent, Host, Score 1–100 human attention, Datetime UTC, Summary, Detail link).

Rules:

- Agents write only in their own host workspace (+ allowed code paths)
- Never write Cursor artifacts into `.claude/` or `.codex/` (and vice versa)
- Workspace files are evidence — promote outcomes into `.ai/*.md` or harness JSON as appropriate
- Do not store secrets in workspace files

## Harness JSON (optional)

When amir_project harness tools are used:

| Path | Role |
|------|------|
| `.ai/state/*.json` | **Truth** — orchestrator updates via state tools |
| `.ai/views/*.md` | **Generated** — regenerate via tools; do not hand-edit as truth |
| `.ai/project.md` / `design.md` | Human-readable goal/design — not replaced by JSON |

If hand-edited JSON conflicts with tools, run doctor and reconcile — do not fork truth in chat.

## Single-writer discipline (harness)

| Data | Writer |
|------|--------|
| `tasks.json`, `decisions.json`, `status.json`, `cost.json` | **Orchestrator only**, via `tools/` state commands |
| `activity.jsonl` | **Append-only** |
| `views/` | Regenerated by tools |
| `.ai/reports.md` | Orchestrator or the agent that just published a report |

Workers and QA **propose** changes in artifacts; orchestrator merges to shared docs / JSON.

## Project isolation

- One `.ai/` + host trees **per project** repository root
- Agents must not read or write another project's trees unless explicit multi-repo spec
- `/amir:create_project` / `/amir:onboard_project` initialize layout — see
  `templates/project-layout.md`
